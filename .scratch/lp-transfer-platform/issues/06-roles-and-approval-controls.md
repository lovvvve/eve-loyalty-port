# 确定角色权限与审批控制

Type: grilling
Status: resolved
Parent: [规划 LP 转账信息管理平台](../map.md)
Blocked by: 02, 05

## Question

成员、财务审核者、游戏内执行者、管理员与只读审计者分别能查看和操作什么？需要决定申请人与审批人、审批人与执行人是否必须分离，是否按金额或风险触发多级审批，谁能代建、驳回、强制完成、冲正或调整余额，以及所有越权操作需要什么理由和审计记录。

## Answer

采用由平台显式授予、可组合、全 LP 发行方范围生效的专业业务角色。EVE 军团职位只作资格证据，不自动映射权限；角色组合取权限并集，但职责分离、利益冲突和审批人数约束始终优先。

### 权限矩阵

| 角色 | 允许 | 禁止或限制 |
|---|---|---|
| 成员 | 查看自己的权益、订单与时间线；提交和撤回订单；提交角色及成员结算公司申请 | 查看他人数据；处理涉及本人利益的管理步骤 |
| 财务经办者 | 查看全局权益与库存；采集库存快照；提交产出/归集补录、权益调整和财务规则提案；代建订单 | 批准自己的经办结果；凭经办角色执行或复核 |
| 审批者 | 批准或拒绝订单和财务提案；因财务原因取消尚未领取的订单 | 覆盖原始记录；没有提案直接改账 |
| 执行者 | 领取、续期、释放和执行订单；上传执行登记与执行更正 | 绕过审批或强制完成 |
| 复核者 | 裁定精确转出、确认未转或进入执行异常 | 修改执行者原始登记；无审批完成订单 |
| 管理员 | 管理成员、角色冲突、公司绑定、成员合并、角色治理、账户停用、技术配置及身份/系统冻结 | 管理员身份本身不包含财务、审批、执行、复核、改账或强制完成权限 |
| 审计者 | 全局只读查看与导出权益、库存、订单、角色授予、审计日志和原始凭证 | 审计角色本身不能修改；密钥、完整 token 和受限安全备注不可见。人员可以兼任其他写入角色，因此不自动代表独立审计人 |
| 同步服务身份 | 后台读取 ESI 并保存同步数据 | 不能登录管理界面，也不能审批、执行、复核或改变财务事实 |

纯管理员只能查看治理所需的成员、绑定、角色和订单受阻状态；完整账本、库存和证据需要另授财务或审计角色。所有专业角色均为全局范围，不按 LP 发行方缩小。

### 普通订单的两人控制

- 每张订单只需要一名审批者，不按金额增加审批级数。
- 审批、执行、复核三个步骤整体必须至少有两名不同管理成员参与；同一个人不能包办三步。
- 执行者允许复核自己的执行。因此正常组合可以是“甲审批，乙执行并复核”，也可以是“甲审批并复核，乙执行”。
- 受益成员本人不得审批、执行、复核或裁定自己的订单。

### 财务审批矩阵

| 事项 | 所需批准 |
|---|---|
| 普通 LP 转账单 | 1 名审批者 |
| 产出补录、归集量补录、库存快照 | 1 名非经办审批者 |
| 权益调整 | 2 名独立审批者 |
| 军团留存率、最低转账量等财务规则变更 | 2 名独立审批者 |
| FIFO 例外调整 | 2 名独立审批者 |
| 异常结案的账务处置 | 2 名独立审批者 |

- 经办者或调查者不计入批准人数，也不能批准自己的提案；换一个绑定角色登录仍是同一平台成员。
- 任何一名合格审批者都能拒绝提案；拒绝必须写明正式理由，该版本随即终止。
- 提案内容变化必须生成新版本并使旧审批全部失效。
- 已合法完成的历史审批默认保留。批准者后来停权时，未完成动作由仍有权限者接替；若停权涉及账号失陷或违规，管理员可冻结尚未执行事项并要求重新审批。
- 没有任何角色或线下恢复入口可以跳过审批、无证据强制完成、直接覆盖账本或删除终态。

### 利益冲突

成员是订单、权益补录或调整、成员结算公司绑定、成员合并或异常账务处置的本人利益主体时，不得作为批准者、执行者、复核者或最终裁定者。管理员禁止模拟成员；代理行为必须使用显式代建或管理操作，并记录真实操作者和代理对象。

### 角色授予、复核与撤销

- 管理类角色要求持有人当前至少有一个绑定角色属于主军团；离团、资格失效或到期时立即暂停，重新入团不会自动恢复高权限。
- 所有管理类角色每 90 天复核，并可设置更早到期；专业角色和管理员角色正常续期均需另一管理员确认，任何人不能自续。
- 一名管理员可给其他成员授予普通专业角色，但不得给自己授予任何角色。
- 新增管理员或管理员失效后的重新授予需要两名现有管理员；平台正常状态至少维持两名有效管理员。
- 一名管理员可撤销普通角色；永久撤销管理员角色需要两名其他管理员。成员可以主动放弃自己的角色。
- 任一管理员可紧急暂停疑似失陷账号；人工安全冻结必须由另一管理员批准解除。自动条件冻结可在证据恢复后按规则解除。
- 授予执行者前必须保存其确有游戏内军团 LP 转账能力的资格证据；资格失效时暂停执行者角色。
- 管理者被暂停时，其历史行为不删除；未完成动作停止。尚未游戏操作的领取可释放，无法确认是否已经操作的执行中订单进入执行异常。

### 身份治理批准

- 普通首次成员结算公司绑定由一名非本人管理员批准。
- 成员合并和历史成员结算公司改绑给另一成员需要两名独立管理员批准。
- 任何管理员不得批准涉及自己的身份、绑定或合并事项。
- 执行领取前的财务取消由审批者处理；身份或系统原因取消由管理员处理，均需成员可见正式理由。

### 启动、恢复与会话

- 首次部署登记两名初始管理员，并保留部署级线下恢复入口。线下恢复只能重建管理员治理能力，不能修改财务事实或绕过业务流程，且必须产生不可删除审计事件。
- 成员完成一次 EVE SSO 登录后，整个仍然有效的平台会话可执行其已授权操作；本决策不要求每项敏感操作再次 SSO。

### 权限审计

角色授予、续期、批准、拒绝、暂停、撤销、越权拦截、冻结解除和线下恢复全部写入任何角色都不能删除的权限审计日志。至少记录平台成员 ID、登录角色、当时的角色与权限快照、目标、提案版本或内容哈希、结果、时间和理由；密钥、授权码及完整 token 永不进入日志。
