# 忠诚星港（Loyalty Port）

面向单一 EVE Online 主军团的 LP 权益、转账、对账与审计平台。

> **当前状态：产品规格规划中。** 本仓库目前保存领域模型、官方能力研究和决策工单，尚无可部署的应用程序，也尚未选择最终技术栈。

## 项目定位

在 LP 百税制度下，主军团集中取得成员产生的应税 LP，再由游戏内有权限的人员手工转入成员指定的结算公司。忠诚星港用于管理这一过程中的信息与责任链，包括：

- 将多个 EVE 角色归集为一个平台成员；
- 按 LP 发行方分别计算成员 LP 权益；
- 管理成员唯一有效的结算公司；
- 处理转账申请、预占、审批、库存排队和人工执行；
- 保存执行凭证、复核结果、异常调查和调整记录；
- 为成员、财务、管理员和审计者提供受控视图。

平台只管理信息闭环，**不会调用游戏接口自动执行 LP 转账**。

## 核心业务闭环

```text
Corporation Project 快照
          ↓
推导成员 LP 产出与归集量
          ↓
扣除军团留存并形成成员权益
          ↓
成员申请 → 预占权益 → 审批
          ↓
等待/分配军团 LP 库存
          ↓
游戏内人工转账 → 执行登记 → 人工复核
          ↓
完成 / 确认失败 / 执行异常与对账调整
```

权益计算遵循：

```text
推导 LP 产出 = 本次项目累计值 - 上次完整快照累计值
推导归集量 = 推导 LP 产出 × 对应区间的游戏 LP 税率
成员 LP 权益增加 = 推导归集量 ×（1 - 军团留存率）
```

不同 LP 发行方严格分账，不允许跨发行方合并或折算。

## 已确立的原则

- **追加而不改写**：账本、审批、执行与纠错均保留原始历史；终态订单不能重新打开。
- **权益与库存分离**：成员权益不因主军团当前库存不足而消失，库存不足只会延迟执行。
- **游戏事实优先**：平台推导值不能冒充 ESI 官方税收或转账流水。
- **人工执行必留证**：执行者登记实际接收公司、发行方、数量和时间，并上传原始凭证。
- **异常禁止盲目重试**：结果不确定、错额、错公司、错发行方或疑似重复转账时锁定订单并调查。
- **平台自主授权**：EVE 军团职位只作为资格证据，不自动等同平台财务或管理权限。
- **利益冲突隔离**：管理成员不得审批、执行、复核或裁定涉及本人利益的事项。

完整术语定义见 [`CONTEXT.md`](CONTEXT.md)。

## EVE 数据能力边界

官方 ESI 当前不能提供完整的玩家军团 LP 管理闭环：

- 没有玩家军团 LP 余额接口；
- 没有 LP 税收流水；
- 没有军团间 LP 转账日志或转账写入接口；
- EVE SSO 只能证明某个角色完成了授权，不能证明现实真人身份或自动发现其全部角色；
- `earn_loyalty_point` Corporation Project 快照只能受控推导成员 LP 产出。

因此，平台账本是业务事实主线，ESI 是身份验证、数据输入和校验来源；军团库存及实际转账仍需游戏客户端凭证和人工复核。

## 范围边界

### 计划支持

- 单一主军团；
- 一名成员绑定多个 SSO 角色；
- 一名成员同时绑定一家有效成员结算公司；
- 成员权益、军团留存和军团库存分账；
- 转账申请、审批、人工执行登记、复核和对账；
- 期初余额与当前绑定导入；
- 查询、报表、导出、通知和不可删除审计轨迹。

### 不在本项目范围内

- 平台直接在游戏内执行 LP 转账；
- 多主军团、联盟级多租户或对外 SaaS；
- 完整重建切换日前的全部历史交易；
- LP 商店兑换、物品物流、市场销售及 ISK 分账。
